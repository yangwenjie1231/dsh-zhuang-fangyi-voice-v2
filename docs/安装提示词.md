# 安装提示词（复制给任意 AI 助手用）

> 这份文档就是**给你复制的提示词**。把它整段粘给你的 AI 助手
> （Claude Code / Cursor / DSH 自己都行），它会按步骤替你配好环境。
> 也可以自己照着做 —— 每一步都有"怎么确认成功"。

## 直接复制这一段

```text
帮我在这台机器上装好「庄方宜语音」——一个中文 TTS 的 DSH 插件。

仓库：(把这里的路径换成你的实际路径，例如 D:\dsh-zhuang-fangyi-voice 或 ~/dsh-zhuang-fangyi-voice)

请按顺序做，每步做完先报告结果再继续，**不要跳步**：

1. 先跑环境体检，**它会把后面所有决策依据一次给全**：
   python -m zfh_voice doctor
   它会报：Python 版本、GPU 型号/显存/驱动、onnxruntime 与 torch 是否可用、
   磁盘剩余、已装内容，并**直接给出该装哪套模型和下一步命令**。
   （这一步不需要任何第三方依赖，裸机器上也能跑。）

2. 按体检的建议装 Python 依赖（在仓库根目录执行）：
   ⚠️ **先确认"哪个 python"** —— 这是首次部署最常见的坑：
      插件按 配置 → 环境变量 ZFH_VOICE_PYTHON → <仓库>/.venv → PATH 找解释器，
      而 PATH 上那个 python 往往**没装 torch**（系统 Python、没激活的 conda）。
      自检：python -c "import importlib.util,sys; print(importlib.util.find_spec('torch') is not None)"
      若输出 False，请换成装了 torch 的那个解释器，**记下它的绝对路径**——第 5 步要写进插件配置。
      别只 pip install torch 了事：那装进的是你敲命令时那个 python，不一定是插件会用的那个。
   - 通用：pip install -r requirements.txt
   - 体检说"有 N 卡且 torch 未装"、你希望桌宠立刻说话：
     额外 pip install torch torchaudio
     （RTX 50 系必须 torch>=2.7 + cu128，否则报 "no kernel image is available"）
   - 没显卡就别装 torch，用默认 onnx 后端（慢一些但能跑）

3. 下载模型（约 1.5GB）：
   python download_models.py
   体检说磁盘紧张就用 python download_models.py --precision int8
   完成后 python -m zfh_voice status 应显示"就绪"。
   下载优先走 ModelScope（国内快），失败自动回退 GitHub。

4. 自测能不能出声（**先别碰 DSH**）：
   python -m zfh_voice say "今天天气不错，我们一起出去走走吧。"
   默认输出 out/out.wav。播放它，确认是中文女声、不是杂音/静音。
   如果报错或没声音，**停下来把完整报错发我**，不要继续。

5. 装成 DSH 插件：
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\install-dsh-plugin.ps1
   然后**重启 DSH**（ESM 模块有缓存，disable→enable 对入口文件不够）。
   并把解释器与后端写进宿主 profile 的 patch 层
   （$DSH_HOME/profiles/<profile>/cordis.patch.yml）：

   ```yaml
   - id: zhuang-fangyi-voice
     config:
       python: '<第 2 步记下的那个 python 绝对路径>'
       backend: torch                      # 有 N 卡用 torch，否则 onnx
       gsvRoot: '<GPT-SoVITS 检出目录>'      # torch 后端需要
       modelDir: '<模型目录，建议放仓库外>'
   ```

6. 验证插件挂上了：
   - DSH 宿主日志里应出现「庄方宜语音：已挂载 zfhVoice 服务」
   - 若环境没配好，日志里还会跟一段**可照做的指引**（缺什么 + 敲什么命令）；
     按它做完再重启 DSH 即可
   - 桌宠插件的设置页 → 语音 → 「合成服务」那一行应显示"运行中"，而不是"未运行"

7. 试一句：桌宠设置页点「试一句」。会真合成一句并播放。
   如果失败，把设置页那行错误信息原样发我 —— 它会带结构化原因
   （缺依赖 / 缺模型 / 找不到 python / 端口占用 / 超时）。

约束：
  · 不要用绝对路径硬编码进任何配置文件 —— 插件自己知道装在哪儿；
  · 任何一步失败就停下报告，不要把后面的步骤硬跑过去；
  · 没有 GPU 就别装 torch。
```

## 装完之后：怎么知道现在到底是什么状态

插件对外挂了一个 `zfhVoice` 服务，DSH / 桌宠 / 你自己都能问它：

| 想要什么 | 怎么拿 |
|---|---|
| **环境缺什么、该敲什么** | `zfhVoice.diagnose()` → `{ran, ok, failure:{kind,summary,commands}, guidance}` |
| **模型现在在不在显存里** | `zfhVoice.status().modelLoaded`（`true`/`false`/`null`=未知） |
| 服务进程在不在 | `zfhVoice.status().processAlive` |
| 当前常驻策略 | `zfhVoice.status().resident`（意图）/ `idleAction` / `idleStopSec` |
| **运行时开关常驻** | `zfhVoice.setResident(true/false)` |
| 切换释放档位 | `zfhVoice.setIdleAction('stop' \| 'unload')` |

命令行侧等价物：`python -m zfh_voice doctor`（人看）与
`python -m zfh_voice doctor --json out.json`（程序读）。

> `resident`（配置意图）和 `modelLoaded`（真实状态）是**两件事**：
> 配了常驻但服务刚启动、模型还在加载时，前者是 `true`、后者是 `false`。
> 判断"现在占不占显存"要看 `modelLoaded`。

## 各步在做什么 / 怎么确认成功

| 步骤 | 做什么 | 确认成功的标志 |
|---|---|---|
| 1 | 环境体检 | `doctor` 打出报告，末尾有"建议"和"下一步" |
| 2 | 装依赖 | 再跑 `doctor`，"Python 依赖"那行不再列缺失项 |
| 3 | 下模型 | `python -m zfh_voice status` 说"✓ 就绪" |
| 4 | **不碰 DSH 先出声** | 播 `out/out.wav` 能听到中文女声 |
| 5 | 装 DSH 插件 | `install-dsh-plugin.ps1` 报告"已复制 …Python 源文件 N 个" |
| 6 | 重启 DSH | 宿主日志出现「已挂载 zfhVoice 服务」，且**没有**跟着警告 |
| 7 | 试一句 | 设置页显示"服务正常 · torch · 3200 ms"之类 |

**第 4 步是最重要的分界线**：它证明"模型 + python 环境"没问题。
如果第 4 步就不出声，问题一定在 Python 侧，与 DSH 无关 ——
带着完整报错去看 README.md 的"故障排查"，别在 DSH 里瞎试。

**第 6 步是新用户最容易卡住的地方**：挂载成功 ≠ 环境就绪。
装好插件但依赖/模型没装时，宿主日志会额外打一段指引（形如
「庄方宜语音：环境还没配好 —— 缺 Python 依赖：numpy, onnxruntime」后跟命令）。
**照着敲完再重启 DSH**，不用去猜。

## 后端怎么选（直接影响体验）

| | 依赖 | 速度 | 占显存 | 什么时候用 |
|---|---|---|---|---|
| **torch** | torch + torchaudio | **RTF ≈ 0.45**（6 秒音频约 3 秒） | 要（几 GB） | 有 N 卡，想让桌宠"立刻说话" |
| **onnx** | 只要 onnxruntime | RTF ≈ 6（6 秒音频约 37 秒） | 不要 | 没显卡 / 不想占显存 |

> ⚠️ **onnx 后端逐句交互基本不可用**：37 秒后气泡早消失了。
> 桌宠那边可以把「每次朗读字数上限」调到 20~30 字缓解，但体验仍有限。
> 有卡就上 torch。

## 桌宠那边怎么接（已经做好了，无需改代码）

桌宠插件会自动发现本插件挂的 `zfhVoice` 服务：

  · **装了本插件** → 桌宠把合成**委派**给它（进程由本插件管）；
  · **没装本插件** → 桌宠退回"自己起进程 + HTTP"（要求服务在 8765 端口）；
  · **两种都没有** → 桌宠退回固定台词，聊天完全不受影响。

设置页的四处开关（都在桌宠的「语音」分组里）：

| 设置 | 作用 |
|---|---|
| 念出回答 | 总开关：要不要把 AI 的回答念出来 |
| 让语音模型常驻 | 开：一直占显存，合成立刻开始；关：空闲后自动释放显存 |
| 空闲多少秒后释放 | 非常驻模式下多久没说话就释放（0 = 不释放） |
| **释放方式** | `stop` 杀进程（全释放、恢复慢）；`unload` 只卸模型保留进程（**显存同样释放、恢复更快**） |

状态那一行会显示三种情况，**据实上报**：

| 显示 | 含义 |
|---|---|
| 运行中（模型已加载） | `modelLoaded: true` —— 正占着显存，合成立刻开始 |
| 运行中（已释放显存） | `modelLoaded: false`、进程还在 —— 下次合成会重新加载 |
| 未运行 | 进程已停 / 还没起来 |

另有「启动服务」/「停止并释放」两个按钮，用于**立刻**起或释放 ——
不等空闲超时。桌宠**只停自己起的**进程；你自己在终端起的服务，它只连不杀。

### 两档释放怎么选

| | 显存 | 恢复代价 | 适合 |
|---|---|---|---|
| `stop` | 完全释放（连进程一起） | 进程启动 + 导入 + 加载 + 预热 | 长时间不用、要把资源还干净 |
| `unload` | **同样释放**（模型卸掉） | 加载 + 预热（省掉进程启动与导入） | 频繁用、只想不占显存 |

> 实测同一句话：冷启动合成 ≈ 35s；`unload` 后恢复更快，因为 Python 进程、
> 已导入的模块都还在。桌宠默认 `stop`（保守），想更快就在设置里改 `unload`。

## 音质两个开关（默认已是最稳，想调再看）

### 短句不稳 → 已默认修好

不传种子时 GPT-SoVITS 每次采样都不同，而且**句子越短波动越大**：
4 字句时长变异 **23.5%**（`让我想想` 曾产出 0.74s，正常 1.22s，等于被截断），
10 字句 17.0%，24 字句只有 10.3%。

本插件**默认固定种子 42**，所以短句时长稳定、可复现。

| 想要 | 怎么做 |
|---|---|
| 默认（推荐） | 什么都不用做，`seed` 默认 42 |
| 换一个种子 | 插件配置 `seed: 7` |
| 恢复随机（不推荐） | 插件配置 `seed: null` |

> 固定种子后**时长**完全可复现；波形仍有约 −51 dB 的浮点差异
> （CUDA 原子操作导致，相关系数 0.999997），**听觉上不可闻**。

### 觉得"糊" → 亮度补偿（默认 `auto`，已自动处理）

模型输出 32 kHz，素材是 48 kHz。下采样在 16 kHz 附近的抗混叠滤波滚降，
让 **12–16 kHz 比原声低**，听感偏闷。

插件配置 `brightnessDb` **默认 `'auto'`** —— **按模型版本自动选校准值**，
你不必手动调：

| 模型 | auto 解析为 | 为什么 |
|---|---|---|
| v2 / v1 | **0**（不动） | 它的 8–12k 已**偏亮** 4.2 dB、12–16k 已对齐 → 补偿只会让 12–16k 过冲 |
| **v2Pro / v2ProPlus** | **1 dB** | 两个频段都接近原声，只需极少补偿 |
| v3 / v4 | 0 | — |

> **校准口径是「长文本」**（421 秒全文，你的实际用途）。实测合计频谱偏差：
> v2 `0dB → 6.04` vs `3dB → 8.51`（**0 更优**）；
> v2Pro `0dB → 1.60` vs `1dB → 1.12`（**1 更优**）。
>
> ⚠️ **短句与长文本的偏好相反**（短句最优 3 dB）—— 因为长文本由多段拼接，
> 段间过渡抬高了高频。这里**以长文本为准**；短句用户可自行调高。

**想手动控制**才填数字：

| 配置 | 效果 |
|---|---|
| `brightnessDb: 'auto'` | 默认，按模型版本自动选 |
| `brightnessDb: 0` | **显式关闭**（与 auto 语义不同：一定不动输出） |
| `brightnessDb: 2` | 强制 +2 dB（取值范围 0~12） |

> **这是听感补偿，不是信息恢复。** 实测素材本身有效带宽约 16 kHz
> （16–20 kHz 只有 −60 dB、20–24 kHz 是噪声底），所以换 48 kHz 模型
> 也补不回真实信息。

> **拿不准就先 auto**；觉得闷再**逐级**加到 1~2，不要直接上 3。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 装了插件但状态显示"未运行" | DSH 没重启（ESM 缓存） | 重启 DSH |
| 日志有「环境还没配好 —— 缺 Python 依赖」 | 第 2 步没做 | 照日志里给的命令装依赖 |

## 首次部署最容易踩的 6 个坑

> 这一节是**实际部署时踩出来的**，不是想象清单。前 4 个属于"静默失败"——
> 症状与真实原因相距很远，不知道的话很难查。

### ① python 用错了（最常见）

**症状**：服务起不来，报错看不出跟解释器有关。

**原因**：插件按 `配置 → ZFH_VOICE_PYTHON → <repo>/.venv → PATH` 找解释器，
而 PATH 上的 `python` 往往没装 torch（系统 Python、没激活的 conda 环境）。

**自检**（插件现在会主动警告，宿主日志里搜「没有 torch」）：

```
python -c "import importlib.util,sys; print(importlib.util.find_spec('torch') is not None)"
```

**修**：在插件配置里写死 `python: <带 torch 的解释器绝对路径>`。

> ⚠️ 别只 `pip install torch`：那装进的是**你敲命令时**那个 python，
> 不一定是插件会用的那个。

### ② 模型目录里该放什么（按后端不同）

**症状**：`找不到可用的模型目录（require='任意'）`。

校验规则是"目录里得有**能支撑推理的东西**"，只有参考音频不算：

| 后端 | 模型目录里必须有 |
|---|---|
| `onnx` | 7 个 ONNX + `G2PWModel/` + `chinese-roberta-wwm-ext-large/` + `ref/default.wav` |
| `onnx`（v2Pro 包） | 上面那些 **再加 `sv_after_fbank.onnx`**（说话人编码器） |
| `torch` | `torch_weights/`（`zfh-e4.ckpt` + `zfh_e6_s186.pth`）**或**让 `gsvRoot` 指向已有检出，外加 `ref/default.wav` |

> **v2Pro 的 ONNX 包多一个文件**。漏了它，`status` 会明确报出来
> （`缺 sv_after_fbank.onnx  (v2Pro 的说话人编码器)`），不会等到合成才失败。
>
> torch 后端的权重**不锁死文件名**：`<名>-e<N>.ckpt` + `<名>_e<N>_s<N>.pth`
> 也认（自己重训或换版本时用得上）。

torch 后端的文本前端取自 `gsvRoot`，**不需要**在模型目录里再放一份 G2PW。

### ③ 别把模型放进仓库目录

**症状**：本来好好的，某次 `git clean -fdx` 之后模型没了
（`models/` 在 `.gitignore` 里，会被一起删掉）。

**修**：模型目录放**仓库外**，用 `modelDir` / `ZFH_MODEL_DIR` 指过去。

### ④ torch 后端必须给 `gsvRoot`

**症状**：明明有显卡、有训练好的权重，却按 `onnx` 跑（一句 37 秒）。

**原因**：`backend: auto` 在没有 `gsvRoot` 时无法确认 torch 可用，于是选 onnx。

**修**：配置里写 `gsvRoot: <GPT-SoVITS 检出目录>`（需含 `GPT_SoVITS/`）。

### ⑤ 改完 `index.js` 必须重启 DSH

宿主的 ESM 模块有缓存，`disable → enable` **不够**。
用 `zfhVoice.status()` 或宿主日志里的挂载行确认新代码生效。

### ⑥ 插件要 enable，不只是拷文件

`tools/install-dsh-plugin.ps1` 只负责**拷或链**；注册与启用走
`plugin_manager install_bundle`（支持 `link:<仓库路径>`，改代码直接生效），
或在插件管理器里把 `include:zhuang-fangyi-voice` 置为 enabled。

## 给插件作者的两条经验（真金白银换的）

1. **探测别 import 大包**。判"装没装 torch"用
   `importlib.util.find_spec('torch')`：**10MB / 0.1 秒**；
   而 `import torch` 是 **406MB / 1.9 秒**。每次 `apply()` 都来一遍的话，
   能把机器的提交量打满 —— Node 报 `Committing semi space failed`、
   Electron（DSH 本体）直接崩。**一个"体检"绝不该吃 400MB。**
2. **体检要缓存**。同一个解释器只探一次（进程级）。
   `apply()` 可能被多次调用（设置变化 / HMR / 测试）。
